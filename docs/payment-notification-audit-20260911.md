# 결제수단 변경에 따른 알림톡 점검

작성일: 2026-09-11

## 현재 결론

- 카드, 간편결제, 계좌이체는 토스 결제 상태가 `DONE`인 경우에만 예약 또는 공판장 주문이 생성된다.
- 예약/주문 생성 트리거가 이용자와 사장님 알림을 적재하므로 결제 완료 알림을 별도로 하나 더 보내면 중복 알림이 된다.
- 기존 이용자 템플릿 문구의 `입금 확인`을 `결제 완료`로 바꾼 V2 템플릿 승인이 필요하다.
- 가상계좌는 기존 코드를 삭제하지 않고 유지하되, 토스 가상계좌 계약 활성화 전에 별도 보완이 필요하다.

## 결제수단별 알림 흐름

| 결제수단 | 결제 직후 상태 | 이용자 알림 | 사장님 알림 |
| --- | --- | --- | --- |
| 카드/간편결제/계좌이체 | `DONE` | 결제 완료 및 예약 요청 접수 또는 주문 접수 | 새 예약 요청 또는 새 주문 |
| 가상계좌 발급 | `WAITING_FOR_DEPOSIT` | 은행, 계좌번호, 금액, 입금기한 | 아직 보내지 않음 |
| 가상계좌 입금 완료 | `DONE` | 결제 완료 및 예약 요청 접수 또는 주문 접수 | 새 예약 요청 또는 새 주문 |

## 템플릿 조정

알리고에서 아래 V2 템플릿을 먼저 승인받고 승인 코드가 나온 뒤 코드 매핑을 교체한다.

1. `USER_RESERVATION_REQUESTED_V2`: `입금 확인` 대신 `결제 완료 및 예약 요청 접수`
2. `USER_ORDER_RECEIVED_V2`: `결제 완료 및 주문 접수`
3. `USER_VA_ISSUED_V2`: 토스 가상계좌 필드와 입금기한 표기
4. `USER_VA_EXPIRED_V1`: 미입금 만료 및 재결제 안내
5. `USER_MARKET_PICKUP_READY_V1`: 공판장 상품 수령 준비 완료
6. `USER_STAY_REMINDER_V1`: 숙박 D-1 일정과 사장님 문의 링크
7. `USER_MARKET_PICKUP_REMINDER_V1`: 수령 당일 시간, 장소, 주류 신분증 안내
8. `USER_REVIEW_REQUEST_V1`: 숙박 또는 수령 완료 뒤 리뷰 요청

결제 실패는 사용자가 결제창에서 바로 확인할 수 있으므로 모든 실패마다 알림톡을 보내지 않는다. 결제는 승인됐으나 내부 예약/주문 생성이 실패한 경우만 기존 관리자 장애 알림으로 즉시 확인한다.

## 토스 가상계좌 전환 전 필수 개발

현재 `finalize_toss_payment_intent`는 `DONE`만 허용하므로 토스 가상계좌 발급 응답인 `WAITING_FOR_DEPOSIT`을 완료 결제로 처리할 수 없다. 계약 활성화 전에 아래를 구현하고 테스트해야 한다.

1. 승인 응답의 가상계좌 정보와 `secret`을 결제 원장에 저장한다.
2. 결제 원장을 `waiting_for_deposit`으로 바꾸고 입금기한까지 객실/재고 보관을 유지한다.
3. `DEPOSIT_CALLBACK` 웹훅의 `secret`을 최초 응답과 비교한다.
4. 웹훅 조회 결과가 `DONE`일 때만 예약/주문을 한 번 생성한다.
5. 취소, 만료, 입금 오류 시 보관 재고를 풀고 이용자에게 상태를 안내한다.

기존 포트원 가상계좌용 테이블과 알림 데이터는 기록 보존을 위해 삭제하지 않는다. 토스 응답 형식에 맞춘 전용 처리만 추가한다.
